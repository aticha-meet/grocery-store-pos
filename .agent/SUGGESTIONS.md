# ข้อเสนอและเรื่องที่ควรตัดสินใจต่อ

เอกสารนี้แยกข้อเสนอออกจาก requirements ที่ให้มา โดยทำฟีเจอร์หลักตามสเปกก่อน และบันทึกทางเลือกเพิ่มเติมให้เจ้าของโปรเจกต์ตัดสินใจภายหลัง

## การตัดสินใจที่ใช้ในรุ่นนี้

1. **แยกเจ้าของร้านกับพนักงานตั้งแต่ต้น** — API ตรวจสิทธิ์จริง ไม่ได้ซ่อนปุ่มอย่างเดียว พนักงานขายและดูบิลได้ เจ้าของร้านเท่านั้นที่แก้สินค้า/สต็อก คืนบิล ดูรายงาน เพิ่มพนักงาน และสำรองข้อมูล
2. **ส่วนลดเป็นจำนวนเงินบาททั้งบิล** — เข้าใจง่ายและตรวจยอดได้ตรง ส่วนลดรายรายการ/เปอร์เซ็นต์ยังไม่ได้เพิ่ม
3. **รับเงินสดและคืนทั้งบิล** — การคืนต้องระบุเหตุผล คืนเงินสดให้ลูกค้าด้วยมือ และคืนสินค้าเข้าสต็อกพร้อมกัน หากต้องการคืนบางรายการต้องเพิ่ม Return/ReturnItem และวิธีเฉลี่ยส่วนลด
4. **นำสินค้าออกด้วย soft delete** — ป้องกันประวัติบิลเก่าเสียหาย บาร์โค้ดของสินค้าที่นำออกยังถูกสงวนไว้ รุ่นถัดไปควรมีหน้าเรียกคืนสินค้าเพื่อไม่ต้องสร้างบาร์โค้ดใหม่
5. **เก็บเงินเป็นสตางค์และเก็บ snapshot ราคาทุน** — ป้องกันปัญหาทศนิยมและกำไรย้อนหลังเปลี่ยนเมื่อแก้ต้นทุนสินค้า กำไรยังเป็นการประมาณแบบราคาทุนปัจจุบันตอนขาย ไม่ใช่ FIFO/ถัวเฉลี่ยจาก lot
6. **รายงานหักบิลคืนจากวันขายเดิม** — ดูยอดขายสุทธิของสินค้าที่ลูกค้าเก็บไว้ได้ง่าย แต่ไม่ใช่รายงานเงินสดเคลื่อนไหวประจำวัน ควรแยกรายงาน cash flow ของคืนต่างวันก่อนใช้ปิดกะจริง
7. **ใช้ไดรเวอร์ Windows พิมพ์ใบเสร็จ 80 มม.** — เปิดทดลองได้โดยไม่ต้องทราบรุ่นเครื่องพิมพ์ และจัดฟอนต์ไทยได้ก่อน ยังไม่ได้เชื่อม `node-thermal-printer` / `escpos` แบบ raw โดยตรง
8. **เดโมมีฐานข้อมูลแยก** — ลองขาย/คืนสินค้าได้ก่อน โดยไม่ใส่บัญชีรหัสผ่านตายตัวลงฐานข้อมูลร้านจริง

## ควรตัดสินใจก่อนนำไปใช้ที่ร้านจริง

- **รุ่นเครื่องพิมพ์และกระดาษ 58/80 มม.**: ทดสอบภาษาไทย ตำแหน่งวรรณยุกต์ ความยาวใบเสร็จ การตัดกระดาษ และบิลยาวหลายรายการ หากต้องการพิมพ์เงียบหรือเปิดลิ้นชัก ให้เพิ่ม adapter ตามรุ่น/การเชื่อมต่อ USB หรือ LAN
- **ชื่อร้านและข้อความในใบเสร็จ**: ปัจจุบันใช้ชื่อ “บ้านร้าน” และข้อความตัวอย่าง ควรเพิ่มฟอร์มชื่อร้าน ที่อยู่ เบอร์โทร และข้อความท้ายบิลก่อนออกเอกสารให้ลูกค้า
- **สิทธิ์ส่วนลดและคืนสินค้า**: ตอนนี้พนักงานให้ส่วนลดได้ แต่คืนทั้งบิลได้เฉพาะเจ้าของร้าน ควรกำหนดเพดานส่วนลด และ PIN อนุมัติสำหรับยอดที่เกินเพดาน
- **รหัสผ่านและการจัดการพนักงาน**: มีสร้างบัญชีและเข้าสู่ระบบแล้ว แต่ยังไม่มี UI เปลี่ยน/รีเซ็ตรหัสผ่าน ปิดบัญชี หรือล็อกหน้าจออัตโนมัติ ควรเพิ่มก่อนใช้หลายคน
- **นโยบายเงินสด**: เพิ่มเปิดกะ/ปิดกะ เงินทอนตั้งต้น เงินเข้า/ออกลิ้นชัก และผลต่างเงินสด ถ้าต้องตรวจเงินจริงตอนปิดร้าน
- **สินค้าเป็นน้ำหนัก/แพ็ก**: รุ่นนี้ขายเป็นจำนวนเต็มหน่วยเดียว ยังไม่แปลงลัง→แพ็ก→ชิ้น และไม่รองรับเครื่องชั่ง ควรตกลงหน่วยก่อนนำเข้าสินค้าจำนวนมาก
- **ข้อมูลตัวอย่าง**: ราคา/บาร์โค้ดเป็นตัวอย่างเพื่อทดสอบ ห้ามใช้เป็นข้อมูลอ้างอิงสินค้าจริง ควรเริ่มร้านจริงด้วยฐานข้อมูลว่าง

## การสำรองและความทนทาน

- มี atomic transaction, SQLite WAL และ synchronous FULL แล้ว แต่ยังควรทดสอบการดับไฟจริงบนเครื่องสำรอง และพิจารณา UPS สำหรับร้าน
- สำรองอัตโนมัติวันละครั้งขณะเปิดแอป และมีปุ่มสำรองด้วยมือ ไม่ได้ทำงานเมื่อเครื่อง/แอปปิดอยู่
- ควรเลือกปลายทางสำรองนอกเครื่อง กำหนดจำนวนวันที่เก็บ และลองกู้คืนจริงเป็นระยะ รุ่นนี้ไม่ลบไฟล์สำรองเก่าเอง
- คำขอขายที่ยังไม่ทราบผลจะถูกเก็บใน local storage ของผู้ใช้ เพื่อกลับมายืนยันรหัสบิลเดิมได้ หากล้าง browser profile ระหว่างบิลค้าง ควรตรวจประวัติบิลก่อนขายซ้ำ
- SQLite และไฟล์สำรองยังไม่เข้ารหัส ผู้ที่เข้าถึงไฟล์ด้วยบัญชี Windows ย่อมอ่าน/แก้ไขข้อมูลได้ บทบาทในแอปไม่ใช่การป้องกันผู้ดูแลเครื่อง

## Desktop และการแจกจ่าย

- คง Tauri + Express + Prisma ตามสเปก โดยบรรจุ Node runtime และ Prisma native engine เข้าแพ็กเกจ จึงมีขนาดมากกว่า Tauri ที่ใช้ Rust backend โดยตรง
- ถ้าภายหลังต้องการลดขนาดตัวติดตั้งมาก ๆ อาจย้าย business logic ไป Rust/SQLite แล้วตัด Express/Prisma ออก แต่ควรทำหลัง flow ร้านนิ่งแล้ว ไม่จำเป็นสำหรับการทดลองนี้
- ก่อนแจกจ่ายหลายเครื่อง ควรเพิ่ม code signing, ทดสอบ clean install/upgrade/uninstall และทดสอบเครื่องที่ไม่มี Node.js/Rust
- WebView2 bootstrapper อาจต้องใช้อินเทอร์เน็ตในการติดตั้งครั้งแรกบนเครื่องที่ยังไม่มี runtime หากต้องติดตั้งแบบออฟไลน์ทั้งหมด ให้เตรียม WebView2 แบบ offline installer เพิ่ม
- ยังไม่ได้ทำการทดสอบกับเครื่องสแกน เครื่องพิมพ์ หรือลิ้นชักจริง การทดสอบคีย์บอร์ดในเบราว์เซอร์ไม่ใช่ผลยืนยันฮาร์ดแวร์

## งานเสริมที่ยังไม่เพิ่ม

- คืนบางรายการ, รายงานเงินสดตามวันที่คืน, ส่วนลดรายรายการ
- อัปโหลดรูปสินค้าและนำเข้ารายการสินค้า CSV พร้อมตรวจบาร์โค้ดซ้ำ
- รายงานเทียบช่วงเวลาก่อนหน้าแบบกราฟซ้อน และค้นหาบิลเกิน 100 รายการด้วย pagination
- เลขบิลแบบลำดับรายวัน/รายปี แทนรหัสอ้างอิงย่อจาก ID
- แจ้งเตือนภายนอกผ่าน Telegram/LINE: รอเลือกช่องทางและจัดการ token อย่างเหมาะสม ไม่ควรผูกการขายกับอินเทอร์เน็ต
- สมาชิก, หลายสาขา/หลายเครื่อง, E-commerce และบัญชีเต็มรูปแบบ อยู่นอกขอบเขตของรุ่นนี้ตามเอกสารต้นฉบับ
